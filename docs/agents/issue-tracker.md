# Specification and ticket workflow

This repository uses no issue tracker.

When a skill asks to publish a specification or ticket, write a Markdown
file directly in this repository. Choose paths with the user when drafting
the replacement specification and tickets.

When a skill asks to fetch a ticket, read the agreed repository file.
Keep specifications and tickets free of tracker statuses and labels.

The authoritative specification is `docs/specifications/WSM_V0_1_SPEC.md`.
Individual v0.1 tickets are in `docs/tickets/v0.1/`. Follow `AGENTS.md` for
ticket scope, learning checkpoints, and explicit approval before every commit.
