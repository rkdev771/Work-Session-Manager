# Domain docs

## Layout and reading rules

This is a single-context repository.

Before exploring the codebase:
- Read root `GLOSSARY.md`, if present.
- Read relevant ADRs in `docs/adr/`, if present.

If these documents are absent, proceed silently. Create glossary entries
or ADRs only when resolved terminology or decisions warrant them.

## Vocabulary and decisions

Use glossary terms consistently when naming domain concepts in
specifications, tickets, code, tests, and proposals.

If a needed concept is missing, reconsider the terminology or raise
the gap during domain modeling.

Surface contradictions with existing ADRs before proposing an override.
