# v0.1 verification audit

This audit covers [ticket 07](../tickets/v0.1/07-verify-workflow-and-document-usage.md)
against the [authoritative specification](../specifications/WSM_V0_1_SPEC.md).
The specification's section 10 describes an earlier implementation snapshot;
the audit uses current code and tests to identify completed behavior.

## Agreed boundaries and coverage decisions

Ticket 07 tests observe independent CLI processes through their exit codes,
output, and persisted JSON. Each test uses temporary home directories;
commands alternate working directories to verify that storage remains stable.
Fixed times enter through the existing public `wsm.cli.main(..., clock=...)`
interface in a test-only Python subprocess wrapper. Ordinary commands and
help also exercise the installed `python -m wsm` and `wsm` entry points.

Pipe barriers synchronize competing CLI commands and signal when a child has
reached a prompt. Timeouts bound test failures; they do not simulate work
duration. There are no added sleeps, CLI clock flags, dependencies, or tooling.
The agreed JSON assertions verify the specified persistence contract rather
than private storage methods. Earlier model, clock, storage, and direct-CLI
tests remain in place.

The audit found that earlier tickets already verify most failure cases and
display requirements. Ticket 07 adds four tests in
[`test_workflow_cli.py`](../../tests/test_workflow_cli.py):

- `test_complete_accountability_loop_persists_across_processes`: a complete
  create/list/start/status/pause/switch/PAUSED-close/resume/ACTIVE-close loop,
  a blocked resume, final JSON, stale selectors, and duplicate-title creation
  followed by identical default/`--all` mappings and immutable archives.
- `test_competing_cli_transitions_allow_only_one_active_session`: start/start
  and resume/start competitors, with one successful command, one clear error,
  one ACTIVE record, and unchanged losing session and selector bytes.
- `test_pending_cli_prompts_survive_refresh_and_reject_changed_records`: six
  cases covering pause, ACTIVE close, and PAUSED close. Refreshes retain the
  captured UUID; competing changes reject stale saves and preserve new data.
- `test_installed_entry_points_offer_complete_help_without_mutating_data`:
  both entry points, no-command help, all command help, and invalid usage.

## How the components work together

The CLI parses one command, collects any input, calls storage, and reports an
exit code. `Session` and `Pause` hold UUIDs and aware datetimes; serialization
converts them to JSON strings. `Session.state` derives the lifecycle from the
start, end, and latest pause. Structural validation checks stored fields;
timing validation checks chronological order and consistent final durations.

`capture_time` converts the supplied/system clock to whole-second UTC.
Duration calculations subtract the start from the endpoint and subtract
pause intervals from that total. An open pause grows between commands while
active duration stays fixed; CLOSED calculations use the saved endpoint.

`SessionStore` uses the saved selector object to resolve a number to its UUID.
Only a listing rebuilds numbers. Brief `fcntl` locks keep inventory, invariant
checks, and atomic JSON replacements coordinated. Pause and close capture
the UUID, timestamp, and exact saved bytes, release the lock during input,
then recheck the saved bytes before committing.

Close builds and validates the full CLOSED record, archives it, then removes
the unfinished copy. Inventory recovery compares duplicate UUID copies;
only a valid matching completion permits unfinished cleanup. A conflicting
copy stops the operation and preserves both records. These existing components
required no implementation changes for ticket 07.

## Validation results and limits

Verification completed on 2026-10-11:

- `.venv/bin/python -m unittest discover -s tests`: **180 tests passed** in
  9.431 seconds (176 retained tests and four new integration tests).
- Targeted `test_workflow_cli.py` run: **four tests passed**, including two
  transition races and six pending-prompt cases.
- Whitespace checks: clean for all ticket 07 additions.
- Independent code-review Standards axis: **zero findings**.
- Independent code-review Spec axis: **zero findings**.

The persistent accountability loop satisfies the v0.1 completion criteria.
No integration defects required runtime changes. The changes remain
uncommitted pending explicit user approval, as required by `AGENTS.md`.

The declared minimum is Python 3.10. This ticket validates the installed
editable package on Linux with Python 3.14.7; it does not establish a tested
multi-version or macOS support matrix. Native Windows cannot use the current
`fcntl` implementation. No type checker is configured in the repository, and
none is introduced for this test/documentation ticket.

Tests prove the specified write-failure and interrupted-cleanup behavior;
they do not simulate power loss or promise hardware crash durability. Manual
system-clock changes without a detectable chronology error remain the
accepted timing limitation. These limits do not add requirements to v0.1.
